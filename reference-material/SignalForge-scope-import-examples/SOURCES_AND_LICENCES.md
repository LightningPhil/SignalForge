# Sources and licences

## Tektronix WFM specification

- Tektronix, Performance Oscilloscope Reference Waveform File Format, part number 077-0220-12.
- <https://download.tek.com/manual/Waveform-File-Format_Instructions_077022012.pdf>

Tektronix describes WFM as its internal save-and-restore format. The specification defines byte order, version identifiers, waveform headers, dimensions, curve buffers and FastFrame structures.

## Tektronix ISF format

- Tektronix FAQ, What is the format of the .isf file?
- <https://www.tek.com/en/support/faqs/what-format-isf-file>

Tektronix states that an ISF file is the response to the instrument's WAVFrm? query. It consists of a waveform preamble and an IEEE 488.2 binary block. The exact response is documented in each instrument's programmer manual.

The included representative_pulse.isf is generated by this project. It does not contain third-party measured data.

## PicoScope CSV conventions

PicoScope examples show a two-row heading. The first row contains names such as Time and Channel A. The second row contains parenthesised units such as (us) and (V).

- Pico support example with analogue time units:
  <https://www.picotech.com/support/viewtopic.php?t=14271>
- Pico support example with digital channels:
  <https://www.picotech.com/support/viewtopic.php?t=42774>

The included CSV is generated by this project. Its layout follows these published examples.

## PicoScope HDF5 conventions

Pico Technology documents an HDF5 arrangement with one group per channel, a one-dimensional dataset per waveform buffer, and timing information for start time and sample interval. A root-level Comments attribute describes the structure.

The included HDF5 file is generated by this project to exercise that documented arrangement. It is a reference fixture, not a byte-for-byte claim about every PicoScope 7 release. Replace or supplement it with a real work-instrument export.

## RigolWFM readers, browser reference and added fixtures

- Repository: <https://github.com/scottprahl/RigolWFM>
- PyPI package: <https://pypi.org/project/RigolWFM/>
- Source commit used: `159e647c0b74e1d73d0ad589149e1c26e1610b26`.
- Package version used by the Python reference: `1.5.0`.
- Licence: BSD 3-Clause.

RigolWFM supplies the Python parser used here for Keysight, Teledyne LeCroy and Rigol. It also supplies the browser viewer snapshot under `third_party/rigolwfm_web_reference`, including Kaitai-generated JavaScript parsers and the normalisation code in `app.js`. The R&S reader in this bundle follows that implementation but directly preserves XYDOUBLEFLOAT time values and performs stricter byte-count validation.

The corresponding format-relevant Kaitai `.ksy` source files are included under `third_party/rigolwfm_kaitai_schemas`, allowing TypeScript generation without reconstructing schemas from generated JavaScript.

The complete BSD 3-Clause text is included as `third_party/RIGOLWFM_BSD_3_CLAUSE_LICENSE.txt`.

Three R&S `.Wfm.csv` exports from the same BSD-licensed corpus are included under `reference_exports/rohde_schwarz`. They provide an independent, full-array comparison for float32, int8 scaling and XYDOUBLEFLOAT time/value decoding; `tests/test_vendor_reference_exports.py` checks them.

## Keysight/Agilent BIN references

- Keysight, Binary Oscilloscope File to MATLAB Translator Program:
  <https://www.keysight.com/us/en/lib/software-detail/programming-examples/binary-oscilloscope-file-to-matlab-translator-program-1185953.html>

Keysight's reference describes reading the file header, waveform count, point count, X/Y units, X increment and origin before reading the voltage vector. It lists official `points10.bin` and `myFileName.bin` examples. The redistributable fixtures included here come from the BSD-licensed RigolWFM test corpus instead.

The AGxx layouts used by this bundle are recorded in the included `AgilentAgxxBin.js` generated parser and in `FORMAT_NOTES_ADDITIONAL_BRANDS.md`.

## Rohde & Schwarz saved waveform reference

- Rohde & Schwarz, Working with acquired waveform data in Python:
  <https://www.rohde-schwarz.com/us/applications/working-with-acquired-waveform-data-in-python_56279-1165008.html>

Rohde & Schwarz states that RTP, RTO and RTE instruments share a binary waveform storage format and create two files: a waveform description `*.bin` and waveform data `*.wfm.bin`. Its official `RTxReadBin` reader supports more waveform and acquisition types than the deliberately bounded reference in this bundle.
